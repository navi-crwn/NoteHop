HOP · 暗号化ノート＆ドキュメント

ブラウザ内で暗号化、瞬時に安全シェア

NoteHop は端末から送信される前にブラウザ内で AES-256-GCM 暗号化を実行します。復号キーはURLフラグメント（#）にのみ存在するため、サーバーは内容を一切読み取れません。n.hel.ink の短縮リンク、オープンソース（MIT）。

NoteHop の機能

  • 端末内 AES-256-GCM 暗号化

    お使いのブラウザが保存前に暗号化。キーはURLフラグメント（#）に含まれ、サーバーへ送信されることはありません。

  • ゼロ知識（Zero-knowledge）サーバー

    サーバーには暗号化されたデータのみが保存されます。管理者やデータベースダンプであっても閲覧不可能です。

  • 自動消滅と1回限りの閲覧

    1回閲覧されたら即座に消去する設定や、10分・1時間・1日・30日後の自動消滅タイマーに対応。

  • リンクごとの柔軟な権限設定

    オーナー用、閲覧専用、編集可能、返信専用、チェックリスト専用など用途に応じた個別リンクを発行可能。

  • リアルタイム共同編集

    WebSocket 中継を介して、参加者間のエンドツーエンド暗号化を維持したままリアルタイムに共同作業。

  • 多彩なノートフォーマット

    Markdown、インタラクティブチェックリスト、投票、フォーム、シンタックスハイライト付きコード、隔離Webノート。

  • 全アプリ共通サインイン：HOP ID

    HOP ID シングルサインオンでHOPファミリー全体をシームレスに利用可能。匿名ゲスト利用もサポート。

  • Go単一バイナリでのセルフホスト

    約16MBの軽量Goバイナリ1つと内蔵SQLiteで動作。外部ランタイム不要で即時デプロイ可能。

よくある質問

サーバーやホスティング業者は私のノートを読めますか？

いいえ。暗号化はブラウザ内の Web Crypto AES-256-GCM で完結します。秘密鍵はURLのハッシュ（#）に残り、サーバーへは届きません。

ノートのリンクを紛失した場合はどうなりますか？

NoteHop はゼロ知識設計でありバックドアやマスターキーを持たないため、リンクを失うと誰もノートを復号・復元できなくなります。

自分のサーバーでホストできますか？

はい。外部ランタイム不要の単一バイナリとしてコンパイルされます。詳細はリポジトリの README をご覧ください。

不具合やセキュリティ報告はどこへ連絡すればよいですか？

GitHub の Issue、または security@hel.ink 宛にご連絡ください。責任ある情報開示に対応しています。
