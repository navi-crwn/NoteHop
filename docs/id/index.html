HOP · Catatan & dokumen terenkripsi

Terkunci di peramban Anda, dibagikan dalam hitungan detik

NoteHop mengenkripsi catatan Anda secara lokal dengan AES-256-GCM sebelum meninggalkan perangkat Anda. Kunci dekripsi berada di fragmen URL (#), sehingga server tidak dapat membaca data Anda. Tautan pendek bersih di n.hel.ink, open source (MIT).

01

Kemampuan NoteHop

  • Enkripsi klien AES-256-GCM

    Peramban Anda mengunci teks sebelum disimpan. Kunci enkripsi berada di fragmen link (#) dan tidak pernah dikirim ke server.

  • Server zero-knowledge

    Server hanya menyimpan gumpalan teks terenkripsi (ciphertext). Operator server atau dump database tetap tidak bisa membaca catatan Anda.

  • Hapus otomatis & bakar setelah dibaca

    Catatan dapat menghapus diri seketika setelah dibuka sekali, atau kedaluwarsa otomatis setelah 10 menit, 1 jam, 1 hari, atau 30 hari.

  • Hak akses bertingkat per tautan

    Terbitkan tautan berbeda untuk catatan yang sama: pemilik, baca saja, dapat mengedit, balas saja, atau centang saja pada daftar tugas.

  • Kolaborasi langsung real-time

    Menulis bersama secara langsung melalui relay WebSocket dengan enkripsi ujung-ke-ujung yang tetap terjaga antar kolaborator.

  • Beragam format catatan

    Teks Markdown, daftar periksa interaktif, jajak pendapat, formulir, catatan kode berpewarna sintaks, dan catatan web terisolasi.

  • Satu login untuk semua app: HOP ID

    Masuk mulus dengan akun single sign-on HOP ID di seluruh keluarga aplikasi HOP, atau gunakan NoteHop tanpa akun sebagai tamu.

  • Biner tunggal Go mandiri

    Dikompilasi menjadi file eksekusi Go ringan (~16 MB) dengan SQLite bawaan, tanpa ketergantungan runtime eksternal.

Tanya Jawab

Bisakah server atau pengelola membaca catatan saya?

Tidak. Enkripsi berlangsung sepenuhnya di dalam peramban web Anda via Web Crypto AES-256-GCM. Kunci rahasia berada di hash URL (#) dan tidak pernah dikirim ke server.

Apa yang terjadi jika saya kehilangan tautan catatan saya?

Karena NoteHop menerapkan zero-knowledge tanpa kunci master atau backdoor, kehilangan tautan berarti catatan tersebut tidak dapat dipulihkan atau didekripsi oleh siapa pun.

Bisakah saya meng-host NoteHop di server saya sendiri?

Bisa. NoteHop dikompilasi menjadi satu biner mandiri Go tanpa ketergantungan runtime eksternal. Lihat petunjuk di README repo.

Di mana saya dapat melaporkan masalah atau bug?

Buka issue di GitHub atau kirim surel ke security@hel.ink untuk pelaporan kerentanan secara bertanggung jawab.
