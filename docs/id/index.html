HOP · Catatan & dokumen terenkripsi

Terkunci di peramban Anda, dibagikan dalam hitungan detik

Secara bawaan, NoteHop mengenkripsi catatan Anda di browser dengan AES-256-GCM sebelum keluar dari perangkat. Kuncinya ada di fragmen URL (#), sehingga server tidak bisa membaca catatan terenkripsi. Catatan dasar, yang bisa dibaca server, mendapat nama tautan pilihan Anda. Tautan pendek di n.hel.ink, sumber terbuka (MIT).

Kemampuan NoteHop

  • Enkripsi klien AES-256-GCM

    Peramban Anda mengunci teks sebelum disimpan. Kunci enkripsi berada di fragmen link (#) dan tidak pernah dikirim ke server.

  • Server yang tidak bisa membaca catatan terenkripsi

    Untuk catatan terenkripsi, server hanya menyimpan teks sandi, jadi operator dan dump database tidak bisa membaca judul maupun isinya. Catatan dasar disimpan sebagai teks biasa dan ditandai sebagai dasar.

  • Hapus otomatis & bakar setelah dibaca

    Catatan dapat menghapus diri seketika setelah dibuka sekali, atau kedaluwarsa otomatis setelah 10 menit, 1 jam, 1 hari, atau 30 hari.

  • Hak akses bertingkat per tautan

    Terbitkan tautan berbeda untuk catatan yang sama: pemilik, baca saja, dapat mengedit, balas saja, atau centang saja pada daftar tugas.

  • Kolaborasi langsung real-time

    Menulis bersama secara real time lewat relay WebSocket. Pada catatan terenkripsi, semua yang diteruskan relay sudah terenkripsi.

  • Beragam format catatan

    Teks Markdown, daftar periksa interaktif, jajak pendapat, formulir, catatan kode berpewarna sintaks, dan catatan web terisolasi.

  • Satu login untuk semua app: HOP ID

    Masuk mulus dengan akun single sign-on HOP ID di seluruh keluarga aplikasi HOP, atau gunakan NoteHop tanpa akun sebagai tamu.

  • Biner tunggal Go mandiri

    Satu program Go sekitar 20 MB dengan SQLite bawaan, tanpa yang lain untuk dipasang, dan penginstal satu perintah.

Tanya Jawab

Bisakah server atau pengelola membaca catatan saya?

Catatan terenkripsi tidak. Browser Anda mengenkripsinya dengan Web Crypto AES-256-GCM sebelum dikirim, dan kuncinya tetap di hash URL (#) yang tidak dikirim browser ke server. Catatan dasar tidak terenkripsi, dan server bisa membacanya.

Apa yang terjadi jika saya kehilangan tautan catatan saya?

Catatan terenkripsi tidak bisa dipulihkan siapa pun. NoteHop tidak punya kunci utama maupun pintu belakang, jadi tautan adalah satu-satunya jalan masuk. Catatan dasar bisa ditemukan lagi lewat nama tautannya.

Bisakah saya meng-host NoteHop di server saya sendiri?

Bisa. NoteHop dikompilasi menjadi satu biner mandiri Go tanpa ketergantungan runtime eksternal. Lihat petunjuk di README repo.

Di mana saya dapat melaporkan masalah atau bug?

Jangan membuka issue publik untuk kerentanan. Laporkan secara privat lewat GitHub: buka tab Security di repositori, lalu pilih Report a vulnerability. Rinciannya ada di SECURITY.md.
