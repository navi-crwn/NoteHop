HOP · 加密便签与文档

在浏览器本地加密，数秒内安全分享

NoteHop 在便签离开设备前于本地浏览器使用 AES-256-GCM 完成加密。解密密钥仅存在于链接锚点（#）中，服务器绝对无法读取您的文本。在 n.hel.ink 获得简洁短链，开源 (MIT)。

NoteHop 功能亮点

  • 客户端 AES-256-GCM 加密

    内容在浏览器内直接完成加密再保存。密钥仅保存在 URL 片段 (#) 中，从不传输给服务器。

  • 零知识服务器架构

    服务器仅存储密文数据块。即便管理员或数据库被导出，也绝无法窥探您的隐私便签。

  • 阅后即焚与自毁定时

    支持阅读一次后即刻销毁，或在 10 分钟、1 小时、1 天或 30 天后自动过期。

  • 细粒度链接权限

    为同一份便签签发不同权限的链接：所有者、仅只读、可编辑、仅回复或清单仅勾选。

  • 实时协同编辑

    基于 WebSocket 中继提供实时协作，同时在所有协作者之间保持全程端到端加密。

  • 丰富的便签类型

    Markdown 笔记、交互式任务清单、投票、表单、代码便签与沙箱化 Web 便签。

  • 全生态统一登录：HOP ID

    使用 HOP ID 单点登录账户畅行 HOP 全家族应用，亦支持完全匿名的游客便签。

  • 单一 Go 二进制私有化运行

    编译为单一约 16 MB 的轻量 Go 可执行程序，内嵌 SQLite，无外部运行时依赖。

常见问题

服务器或托管商能够读取我的便签内容吗？

不能。加密完全在浏览器中使用 Web Crypto AES-256-GCM 运算。密钥仅留在 URL 锚点（#），从不发送给服务器。

如果我丢失了便签链接会怎样？

由于 NoteHop 遵循严格的零知识架构，且不存在主密钥或后门，链接丢失意味着任何人都无法解密或找回该便签。

我可以部署在自己的服务器上吗？

完全可以。NoteHop 编译为单一独立二进制文件，无外部运行时依赖。参见 GitHub 仓库说明。

如何报告问题或安全漏洞？

欢迎在 GitHub 提交 Issue，或致信 security@hel.ink 进行负责任的安全漏洞披露。
