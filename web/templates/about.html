Zero-knowledge Server menyimpan, tapi tidak bisa membaca

Cara kerja NoteHop

Catatan dienkripsi di browsermu dengan AES-256-GCM sebelum dikirim. Kuncinya ada di bagian setelah tanda # pada link, dan bagian itu tidak pernah dikirim browser ke server mana pun.

1. Kamu menulisTeks hanya ada di tab ini.
2. Browser mengunciKunci acak 256-bit, ditambah password kalau kamu isi.
3. Server menyimpan acakanPlus aturan link: mode, kedaluwarsa, sekali baca.
4. Penerima membukaLink /n/abc#k=… membuka kunci di browser mereka.

Empat jenis link

Baca saja

Untuk berbagi info, password, konfigurasi.

Edit penuh

Siapa pun dengan link bisa mengubah. Bentrok simpan dideteksi, tidak ada yang tertimpa diam-diam.

Tambah saja

Pengunjung hanya bisa menambah baris di bawah. Cocok untuk absensi, kumpulan ide, log laporan.

Centang checklist

Isi terkunci, tapi checkbox - [ ] bisa dicentang. Untuk daftar belanja atau runbook tim.

Satu catatan bisa punya banyak link dengan izin berbeda: misalnya satu link edit untuk tim, satu link baca saja untuk klien. Server menegakkan izin itu, dan setiap perubahan juga harus membuktikan pengirimnya memegang kunci catatan.

Bekukan versi

Bekukan versi membuat salinan permanen catatan saat itu juga, dengan link baca saja yang tidak bisa diubah siapa pun, termasuk kamu. Catatan aslinya tetap bisa kamu edit sebagai draf berikutnya.

Hancur setelah dibaca

Catatan bisa terhapus otomatis setelah dibuka 1, 3, atau 10 kali, atau setelah waktu tertentu. Pembaca diminta menekan tombol dulu, jadi pratinjau link di WhatsApp, Telegram, atau Slack tidak ikut menghabiskan jatah baca. Membuka lewat link admin tidak dihitung.

Blok rahasia di dalam catatan

Ketik /spoiler untuk blok yang terbuka saat diklik, atau /kunci untuk blok yang dienkripsi lagi dengan PIN. Cocok untuk kunci jawaban atau kredensial di tengah dokumen biasa.

Raw & curl

Catatan publik (enkripsi dimatikan) bisa diambil sebagai teks murni:

curl -fsSL https://domain-kamu/raw/nama-catatan

Catatan terenkripsi tidak bisa dibaca lewat /raw, karena server memang tidak punya kuncinya.

Akun

Akun itu opsional. Saat masuk, browser menurunkan dua kunci dari password-mu dengan PBKDF2 (600.000 putaran): satu untuk login, satu lagi kunci brankas yang tidak pernah meninggalkan browser. Daftar catatanmu (judul, kunci, link admin) dienkripsi dengan kunci brankas itu.

Batasan yang perlu kamu tahu

  • Siapa pun yang memegang link lengkap bisa membaca catatan. Perlakukan link seperti passwordnya.
  • Gambar dari situs lain tidak dimuat, supaya pembaca tidak bocor ke pihak ketiga.
  • Status centang checklist dan jumlah baris tambahan terlihat oleh server, tapi isinya tidak.
